# AGENTS Guideline

用于定义 `AGENTS.md` 应如何组织，让 agent 快速判断去哪找什么、能做/不能做什么。

## 目标

1. agent 首次进入仓库后，读 `AGENTS.md` 就能知道去哪找命令、背景和规则。
2. 多层 `AGENTS.md` 的继承与覆盖关系清晰可裁决。
3. 约束尽量短、硬、稳定。

## 建议结构

`AGENTS.md` 通常包含：

1. **文件约定** — 声明去哪找命令、背景和规则。每个 AGENTS.md 必写。
2. **开发环境** — 必需的运行时、首次初始化步骤、已知坑位。
3. **编码风格** — 代码规范、语言用法、项目惯例。
4. **什么时候停、什么时候问** — 需要暂停或请求人工处理的场景。
5. **规则生效** — 继承、覆盖和生效范围规则。

## 文件约定

agent 首次进入仓库时，必须在 `AGENTS.md` 开头看到这个约定：

```markdown
## 文件约定

- 运行 `just` 查看所有可用命令
- 项目背景和模块职责见 `README.md`
- 行为约束见本文档
```

此约定缺失会导致 agent 在错误文件中搜索命令或背景信息。

对 monorepo，root `AGENTS.md` 还应声明子目录约定：

```markdown
- 子目录可能存在该目录专属的 `AGENTS.md`，补充局部规则；根部规则在未被子目录覆盖时继续生效
```

## 开发环境

以下信息 agent 在执行前必须知道，缺失时会直接做错：

- **必需运行时环境**：Node ≥ X、Go ≥ Y、Python ≥ Z 等版本约束
- **首次初始化步骤**：`just install` 或等效命令序列
- **已知环境坑位**：macOS 与 Linux 差异、特定系统需要额外步骤、代理或镜像配置等
- **需要预先配置的外部依赖**：数据库、缓存服务、环境变量、Token 等
- **对执行顺序有强制要求的步骤**：必须先 build 再 test、必须先启动依赖服务再运行等

保持短小、可验证，不展开项目背景或长篇说明。

## 编码风格

覆盖项目级的代码规范、语言用法和跨任务成立的工程约束：

- 语言特化规则：三方依赖使用方式、运行时校验边界、代码组织结构等
- 工程基线：先盘点再改动、只改任务相关文件、不顺手重构、不随意新增模块或入口
- 验证义务：能验证时先验证再交付，无法验证时说明缺口
- 协作立场：以正确性和长期可维护性为先；用户要求与之冲突时先指出风险再讨论折中；交付说明区分已验证事实和未验证假设
- 文档和注释语言：优先使用中文，专有名词除外

不要堆砌语言手册中就能查到的通用规则，只写本项目特定的、会直接影响 agent 决策的约束。

## 什么时候停、什么时候问

列出本项目特有的、agent 必须暂停或请求人工处理的场景：

- 需求有多种互斥实现时停下
- 会影响公开 API 或兼容性但没有明确迁移要求时先确认
- 需要新增模块、入口或执行面时问人
- 需要仓库外权限或敏感配置时请求人工处理
- 无法完成最小验证时明确说明缺口

不写抽象的"当风险过高时停下"，写本项目真实会遇到的场景。

## 规则生效

1. 只有落盘到 `AGENTS.md` 的规则才生效。临时口头要求不视为仓库规则。
2. 子目录 `AGENTS.md` 只覆盖确有必要的局部规则，未覆盖的继承上级；冲突以更近的为准。
3. 对 monorepo，root 定全局基线，子目录补局部特化。不在子目录全量重复根部内容。

## monorepo 约定

1. 根目录 `AGENTS.md` 持有跨子项目通用的约束。
2. 子目录可创建局部 `AGENTS.md`，只补充或覆盖该子目录独有的规则。
3. 子目录 `AGENTS.md` 也应写文件约定。若当前目录无独立 `justfile`，应明确指出命令入口在上级。
4. 仅在确有独立协作边界时才创建子目录 `AGENTS.md`。不要为"看起来完整"铺满。

## 表达要求

1. 每条规则都应直接影响 agent 决策。
2. 使用口语化可执行语言，不写口号、不堆大词。
3. 不混入 README 内容（项目背景、模块职责）或命令细节（构建参数、CLI flag）。

## 不应包含

- 项目背景 → `README.md`
- 模块职责正文 → `README.md`
- 命令使用细节（参数、flag、构建步骤）→ `justfile`；可在 AGENTS.md 中引用但不定义
- 长篇 workflow 说明
- 不能直接改变 agent 决策的泛化表述

## 项目特化约定

项目中可能存在三元体系外的非标准文件（如 `PLAN.md` 作为任务看板）。它们不是控制面文件，但可以在 AGENTS.md 中引用——写清楚"用什么文件做什么事"（如"任务计划写 PLAN.md"），不要把它写入三元体系的文件约定中。
