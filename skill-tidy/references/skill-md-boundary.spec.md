# `SKILL.md` 结构与边界

当你需要判断维护对象的 `SKILL.md` 应保留什么、移出什么时，使用这份 reference。

## `SKILL.md` 的职责

`SKILL.md` 是 skill 的激活时说明文件。agent 判断该 skill 相关后，这个文件应帮助它立即知道：

1. 这个 skill 负责什么。
2. 执行它需要什么输入。
3. 应按什么顺序工作。
4. 接下来该读或该运行哪些附属文件。
5. 如何判断工作已经完成。

若某段内容对以上任一目标都没有帮助，就应重新判断它是否该留在这里。

## 推荐结构

正文没有强制固定模板，但一个有效的 `SKILL.md` 通常只放三件事：

1. **决策树** — 按场景选入口，agent 一眼知道走哪条路。
2. **核心路径的最小可执行指引** — 覆盖 80% 场景，不跳转就能干活。可能是代码示例、步骤清单或模板。
3. **扩展入口** — 简短引用指向 references（迁移、自定义、边缘情况），只在需要时加载。

顺序：决策树 → 示例 → 扩展入口。避免章节越来越多但每节信息密度很低。

## Frontmatter 放什么

frontmatter 只保留元数据：

- `name`
- `description`
- specification 定义的、确有实际意义的可选字段

不要把流程说明、示例或冗长兼容性说明塞进 frontmatter。

## `SKILL.md` 放什么

主文件中应保留：

- 核心场景的完整示例——覆盖 80% 使用场景，agent 打开就能动手
- 决策树——按场景选入口，决定是否需要打开 reference
- 最常违反的关键约定
- 扩展路径的简短引用——指向 references

## `references/` 放什么

遇到以下内容时，应移入 `references/`：

- 扩展场景的示例（迁移、自定义、边缘情况，非核心路径）
- 细节较重，每次都加载会浪费上下文
- 具有规范性，但只会在某些维护步骤中查阅
- 更长的边界条件、规则目录或格式要求

每个 reference 文件都应由 `SKILL.md` 显式链接。

reference 文件自身也应保持单一职责：一份 reference 只承载一类规则、规范摘要、判定表或示例。若 reference 开始同时承担流程入口、模式选择和详细规范，应拆分或把入口逻辑上移到 `SKILL.md`。

reference 不应继续链接多层 reference 形成阅读链。若确有依赖，应优先让 `SKILL.md` 直接链接相关文件，并说明读取条件。

## `scripts/` 放什么

当逻辑具有以下特征时，应移入 `scripts/`：

- 追求确定性
- 会反复复用
- 运行脚本比反复用文字重述更合适

`SKILL.md` 应说明何时运行这些脚本，以及预期结果是什么。

脚本只适合处理可机械判断的问题，例如 frontmatter、链接、目录空壳、文件存在性和固定格式。模式判定、内容边界、设计取舍、风险等级和是否拆分 skill 仍必须由 agent 根据 reference 判断。

## `assets/` 放什么

当文件是静态资源，且其用途是被复制、嵌入或作为输出的一部分被消费，而不是被当作说明阅读时，应移入 `assets/`。

## 通常应删除的内容

以下内容很容易造成长期漂移：

- agent 人设或对话风格要求
- 与 skill 真实任务无关的产品 UI 指引
- 本应放在 skill 之外的仓库级开发规范
- 变更记录式历史信息
- 关于“这个 skill 是如何被写出来的”审校笔记
- 已经在某个 reference 中完整表达的重复说明
- 未被 `SKILL.md` 引用，且无法说明使用条件的孤立 reference
- 声称存在但目录中没有的脚本、模板、命令或校验入口

## 边界判断问题

审查 `SKILL.md` 中某一段时，依次问：

1. 它是核心场景的示例或决策入口吗？是则留在 `SKILL.md`。
2. agent 在激活后是否立刻需要看到它？
3. 它是否会改变"下一步该看哪个文件"？
4. 把它移到 `references/` 后，主文档是否会更清晰且不影响核心执行？

如果是扩展场景的示例或详细规范，前两个答案通常是否，应移入 `references/`。

## 附属文件判断问题

审查 `references/`、`scripts/`、`assets/` 中某个文件时，依次问：

1. `SKILL.md` 是否直接引用它，或是否应当补充直接引用？
2. 它是否有明确读取、运行或消费条件？
3. 它是否与所在目录职责一致？
4. 它是否和其他文件重复、冲突或表达过期规则？
5. 删除它是否会降低 skill 的执行稳定性？

若无法回答前两个问题，通常应删除、合并，或在 `SKILL.md` 中补充明确导航。
